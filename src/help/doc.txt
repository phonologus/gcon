usage: gcon doc [-raw | -html | -man | -text | -http addr] [-path] [name]
       gcon doc [-raw | -html | -man | -text | -http addr] file.icn [name]
       gcon doc -list
       gcon doc ipl
       gcon doc -check
       gcon doc -test [name]
       gcon doc -build [-o dir]

Doc shows Gcon's documentation: the pages in the root's doc directory,
and these help pages. By default it serves the documentation on this
machine and opens the page in the web browser, as go doc -http does:
the installed version's documentation, offline, with every example
program editable and runnable (Run gives it to gcon run, Stop kills
it; a run is killed after 60 seconds). The server runs in the
background: the command returns as soon as the browser command has
(at once, for open and xdg-open), and the server stops a few seconds
after the browser has closed its pages (or after two minutes if no
page ever opens, as in a browser without JavaScript: use -http). The
browser is $BROWSER, run in the foreground so that a terminal browser
such as lynx has the terminal, else open on macOS, else xdg-open where
there is a display. With no browser, or one that fails, doc is an
error: use -text to read the page in the terminal.

With no name, doc shows the index. A name is a page's topic, its path
in the tree without ".md" (internals/protocol), or the last element of
one (protocol), a built-in function or keyword with an entry in the
reference (gcon doc find, gcon doc '&subject'), or a Markdown file's
path. An entry is shown alone, or opened at its place in its page. The
help pages are help/index and help/NAME (help/run). gcon doc -list
lists the topics.

When nothing in the tree has the name, doc looks in the Icon Program
Library: a file (strings) or a procedure (WOpen), or explicitly
ipl/strings, shown from its header comment as Arizona wrote it, apart
from Gcon's own pages. gcon doc ipl lists its files (gcon doc -text ipl
as text); those marked "candidate" are candidates for Gcon's standard
library (doc/ipl-candidates.txt).

Given an Icon source file, doc shows its doc comments, as go doc shows a
package's: the comment at the top of the file, and each procedure,
record and global with the comment directly above it (or an IPL-style
"#:" on its line); given a name too, that declaration alone.
gcon doc comments says how to write them.

The flags are:

	-build
		render the tree as HTML, with its search index, into the
		root's doc/html (build.sh does this).
	-check
		check every page: Markdown that is not the documentation's
		subset, and links to pages or headings that do not exist.
	-http addr
		serve the documentation on addr (host:port) and open no
		browser, in the foreground until interrupted: for a browser
		elsewhere, or a port of your choosing.
		Examples run only when addr is a loopback address (127.0.0.1).
	-html
		print the page's HTML.
	-list
		list the topics and their titles.
	-man
		print the page as roff, to read as a manual page:
		gcon doc -man protocol | man -l -
	-o dir
		with -build: write into dir instead.
	-path
		print the path of the page's HTML file, and open nothing.
	-raw
		print the page's Markdown.
	-text
		print the page as plain text, through $PAGER (default less)
		on a terminal.
	-test
		run the examples (in the whole tree, or of one page or entry):
		each Icon program followed by "Output:" must give that output
		under gcon run, and each other must translate.

See also: gcon help help, gcon doc comments.
