Icon's graphics run in a display server, a separate process that
gcon-vm starts when a program first opens a window and talks to
through a protocol. ./build.sh builds the platform's own: on macOS the
Cocoa server, elsewhere the X11 server where Xlib is installed, and
otherwise none. ./build.sh --withCocoa, --withX11 or --withSDL names
the servers to build instead, the first being the one gcon-vm runs;
GCONGRAPHICS chooses another when a program runs.

	Cocoa (macOS): AppKit, Core Graphics and CoreText. Drawing is
	antialiased and at the display's scale; drawops other than copy,
	and patterns, are drawn as X draws them. Fonts are the Mac's:
	mono is Menlo, sans Helvetica, serif Times, typewriter Courier.

	X11: X's own drawing, so the pictures are Arizona Icon's. Fonts
	are X's core fonts, chosen as Arizona chooses them; DISPLAY
	names the display.

	SDL (only with --withSDL; needs the system's SDL3): portable and
	HiDPI, drawn by Gcon's own rasterizer, antialiased, as the
	headless server is; fonts through CoreText or fontconfig, their
	outlines drawn by stb_truetype.

Whichever server draws, the preprocessor defines _SDL_GRAPHICS, not
_X_WINDOW_SYSTEM, and &features includes "SDL graphics", so programs
that test for X take their portable path; keys are reported as X
keysyms. Image files are GIF, PNG, JPEG, BMP and QOI, read and
written by gcon-vm itself: by extension for WriteImage (any other
is written as GIF), by contents for ReadImage. Not supported: the
colour forms rgb:r/g/b and RGBi:...; iconlabel= is accepted but
never shown.

Antialiasing is Gcon's antialias attribute, a context's: on by
default, it smooths the edges of shapes and text drawn in copy mode
without a pattern, where the server can (not X11's); antialias=off
gives X's covered-or-not pixels, and GCONANTIALIAS=off makes off the
default. Other drawops and patterns are always drawn as X draws them.

On macOS, ICONSDL_META=command makes the Command key &meta, instead
of Option, and ICONSDL_SCALE overrides the display's scale.

A fourth server, the headless one, is always built: it has no display,
and gcon-vm runs it where its default server has none (no X display,
say) or there is no default server, so hidden canvases work anywhere.
A window cannot be opened there: open fails, as Icon's does without a
display. A server GCONGRAPHICS names is used as it is.

See also: gcon help environment, gcon doc graphics.
